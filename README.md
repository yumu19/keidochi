# 経道値 — 北海道を、あなたの色に。

北海道179市町村の旅行経験を記録する、フロントエンドだけで動くWebアプリです。記録はブラウザーのローカルストレージに保存されます。バックエンド、APIキー、アカウント登録は不要です。

## できること

- 北海道の市町村地図をクリック・タップして記録。地図の拡大・縮小・移動にも対応
- 市町村ごとに「未踏 / 通過 / 接地 / 訪問 / 宿泊 / 居住」の6段階、0〜5ポイントを記録
- 経道値（最大895ポイント）、足あとを残した市町村数、訪問数、宿泊数を集計
- 市町村名・かな・カタカナで検索し、14振興局や経験レベルで絞り込み
- 市町村ごとに200文字までのメモを自動保存
- 入力済みの地図・経道値・凡例をPNG画像にし、画像付き共有または保存してXへ添付（メモは含めません）
- 各市町村の経験レベルを含む共有リンクを作成。リンク先は閲覧専用で、自分の保存記録を変更しません
- JSONのバックアップ書き出し・復元、確認操作付きのリセット
- スマートフォン、キーボード操作、動きを抑える設定に対応

「足あと」は通過以上、「訪問」は訪問以上、「宿泊」は宿泊以上の市町村数です。ひとつの市町村につき経験の最高レベルを選びます。札幌市は区に分けず、1市として扱います。初期状態はすべて未踏です。

## ローカルで起動

Node.js 24以上を推奨します（20.19以上の20系、22.13以上の22系にも対応）。アプリの起動・ビルドには外部依存パッケージは必要ありません。

```sh
npm run dev
```

[http://localhost:4173](http://localhost:4173) を開いてください。ポートを変更する場合は `PORT=8080 npm run dev` のように指定します。ES Modulesを使うため、`index.html` を `file://` で直接開かずHTTPサーバーで配信してください。

## ビルド・静的ホスティング

```sh
npm run build
```

生成された **`dist/` の中身**を、GitHub Pages、Cloudflare Pages、Netlifyなどの静的ホスティングへ配置します。サーバー処理やSPA用のリライト設定は不要です。アセットは相対パスなので、`/keidochi/` などのサブディレクトリにも配置できます。

ビルド結果のローカル確認：

```sh
npm run preview
```

ホスティング側の設定は、ビルドコマンド `npm run build`、公開ディレクトリ `dist` です。ブラウザーでの動作に外部CDN、外部フォント、地図APIは使いません。X共有と出典リンクを開くときのみ外部サービスへ移動します。

### GitHub Pagesに公開

[デプロイ用ワークフロー](.github/workflows/deploy-pages.yml)を同梱しています。

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. アプリのソースと `.github/workflows/deploy-pages.yml`、`package.json`、`package-lock.json` を含む変更をコミットして、`main` にpushします。
3. **Actions → Deploy to GitHub Pages** で実行結果を確認します。テスト・ビルドが成功すると、`dist/` が公開されます。

このリポジトリ（`yumu19/keidochi`）の公開先は、標準の設定では `https://yumu19.github.io/keidochi/` です。実際のURLは **Settings → Pages** またはワークフローの `github-pages` 環境に表示されます。リポジトリをforkした場合は、URLのユーザー名とリポジトリ名を読み替えてください。

以降は `main` へのpushで自動更新されます。手動で再公開する場合は **Actions → Deploy to GitHub Pages → Run workflow** で `main` を選択します。`main` 宛てのプルリクエストではテストとビルドだけを実行します。

独自のシークレットや `gh-pages` ブランチは不要です。ワークフローは標準の `GITHUB_TOKEN` とOIDCを使い、公開ジョブにだけPagesへの書き込み権限を付与しています。アセットは相対パスなので、`/keidochi/` 用のベースパス設定も必要ありません。

設定の詳細は [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) を参照してください。

### OGP・Twitterカード

`index.html` と閲覧専用の `view.html` にOGPとTwitterカード（`summary_large_image`）を設定しています。正規URLは `https://yumu19.github.io/keidochi/`、共通画像は `https://yumu19.github.io/keidochi/assets/og-image.png` です。タイトル・説明・画像・画像の代替テキストを静的HTMLに含め、JavaScriptを実行しないクローラーにも渡せる構成です。

共通画像は1200×630pxのPNGで、アプリを紹介する固定のイラストです。利用者のローカルストレージの記録・メモは含みません。利用者自身の記録入り画像は、アプリの「結果をシェア」で別に生成します。

画像とそのSVGソースは `assets/` に収録し、通常のビルドで `dist/assets/` にコピーします。再生成する場合：

```sh
npm ci
npm run og:image
```

画像の再生成時には日本語フォントを使用できる環境が必要です。必要に応じて `OG_FONT_FILE` 環境変数で日本語フォントファイルのパスを指定してください。画像生成ツールは開発用依存で、ブラウザーでは使いません。公開先を変更した場合は、`index.html` と `view.html` のcanonical・OGP・Twitterカードの絶対URLと、画像生成スクリプト内のURL表記も変更してください。

## 保存とバックアップ

画面右上の **「記録のバックアップ・復元」**、または「まちから探す」の **「データ管理」** から操作します。

- **エクスポート**：ローカルストレージに保存した経験・メモ・更新日時を `keidochi-backup-YYYY-MM-DD.json` に保存します。
- **インポート**：保存したJSONファイルを選び、経道値・市町村数・メモ件数を確認して「この内容で置き換える」を押すと、ローカルストレージに反映します。現在の記録は置き換わるので、必要な場合は先にエクスポートしてください。

- 保存キー：`keidochi.records.v1`
- 保存形式：`{ "version": 1, "records": { "01100": { "level": 4, "note": "旅のメモ", "updatedAt": "ISO 8601形式の日時" } } }`
- 保存先はブラウザーのオリジン（プロトコル・ホスト・ポート）ごとです。端末やブラウザーを変えても自動では同期されません。
- ブラウザーのデータ削除で記録も消えます。プライベートブラウズでは終了時に消える場合があります。「データ管理」からバックアップを残してください。
- 復元は現在の全記録を置き換えます。形式と内容を検証し、画面での確認後に反映します。
- 保存できない場合はエラーを表示します。壊れた保存データを検出した場合は、読み込みや明示的なリセットを行うまで記録を停止して既存データを保護します。
- シェア画像には経道値・集計・市町村ごとの経験を色分けした地図・地名・凡例を含めます。メモは含めません。画像はブラウザー内で作成し、画像作成用サーバーには送信しません。
- 投稿文は経道値・足あと数・ハッシュタグ・経験レベルを含む共有リンクです。ローカルプレビューのURLは投稿内容から除外します。

### 記録付きリンクでシェア

「結果をシェア」→ **「記録付きリンクをコピー」** で、各市町村の経験レベルを含むURLをコピーできます。Xの投稿や画像付き共有に含まれるリンクにも、同じ経験レベルが入ります。

- 入力画面は `index.html`、閲覧専用画面は `view.html` です。HTMLと起動するJavaScriptを分離しています。
- 入力画面の **「記録を見る」** から、現在の経験レベルを閲覧画面で確認できます。編集中のメモは移動前に保存します。
- 共有リンクは `view.html#share=v1.…` を開き、地図・集計・市町村ごとの経験を表示します。入力画面と同じ配色で、地図を囲む枠と「閲覧専用」ラベルを表示し、目立つ「自分の記録を入力」ボタンから入力画面へ移動できます。入力フォーム、メモ欄、バックアップ・復元、リセット、シェア操作は閲覧画面にありません。
- 閲覧画面はローカルストレージを読み書きしません。自分の記録の有無・保存機能の可否に関係なく、URLの経験レベルだけを表示します。
- **「自分の記録を入力」** で入力画面に移動し、保存済みの自分の経験・メモを引き続き編集できます。共有記録を自分の記録に取り込む機能はありません。
- 従来の `/#share=v1.…` の共有リンクも、入力処理を読み込む前に閲覧専用ページへ移動します。
- メモと更新日時は共有リンクに含めません。リンクは作成時点の経験レベルのスナップショットで、作成後の変更は自動反映しません。
- 共有リンクが不正な場合や閲覧ページに経験データがない場合は、エラーを表示します。自分の記録を代わりに表示・上書きしません。

経験レベルは `#share=v1.…` のURLフラグメントに格納します。v1は市町村コード順の179市町村を各3ビットにまとめたBase64URL形式です。バックエンドや外部の保存サービスは使用しません。OGPの紹介画像は引き続き共通画像で、個別の入力状態はリンクを開いてから表示します。

### 地図画像を添えてシェア

「結果をシェア」で、入力済みの全体地図を含む1200×1200のPNG画像を作成し、プレビューします。地図を拡大・移動していても、画像には全179市町村を収めます。

- **画像付き共有に対応する端末**：「画像付きで共有」を押し、OSの共有画面でXを選びます。対応可否は実際のPNGファイルに対して `navigator.canShare()` で確認します。画像生成後に別のボタンで共有することで、ブラウザーが要求するユーザー操作の条件を満たします。
- **それ以外の端末、または共有先にXがない場合**：「画像を保存（PNG）」→「Xの投稿画面を開く」の順に進み、保存した画像を投稿に添付します。

静的サイトから開く[XのWeb Intent](https://docs.x.com/x-for-websites/post-button/overview)は投稿文・URL等を渡す仕組みで、ローカルのPNGを自動添付できません。直接のファイル共有には[Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)を使用します。利用できる共有先や投稿文・画像の受け取り方はOS・ブラウザー・Xアプリの対応によります。Web Share APIにはHTTPS（またはlocalhost）が必要です。

画像の作成に失敗した場合は再試行でき、従来のテキストのみの共有も利用できます。X APIキーやバックエンドは不要です。

## テスト

```sh
npm ci

```

Node.js標準のテストランナーと、開発時だけ使用するjsdomで検証します。地図データ179件の整合性、ポイント集計、検索、保存と復元、破損データの保護、容量不足時の保存失敗、画面操作、メモの自動保存、X共有、共有画像の色・全体表示・メモの除外、ファイル共有の対応判定・キャンセル・失敗時の動作、複数タブでの更新、確認付きリセットを対象にしています。記録付きリンクについては、全市町村の経験レベルの復元、不正データの拒否、閲覧画面での操作・ページ移動・タブ切り替え中にローカルストレージの読み書きがゼロであること、入力画面からの閲覧リンクとメモ保存、旧共有リンクのリダイレクトを検証します。jsdomの画面操作テストでは画像生成・共有APIを代替実装に置き換えています。実ブラウザーでの画像描画とOS・Xへの受け渡しは別途確認が必要です。

## データの出典

地図・市町村一覧は北海道の公開データを加工しています（CC BY）。

- [北海道の地図GISデータ【北海道】](https://www.harp.lg.jp/opendata/dataset/1379.html) — 市町村ポリゴン、地名表示用座標
- [道内179市町村／50音別](https://www.pref.hokkaido.lg.jp/link/shichoson/aiueo.html) — 名称・読み・振興局
- [住民基本台帳人口・世帯数](https://www.pref.hokkaido.lg.jp/ss/tuk/900brr/index2.html) — 地図の都市名表示の判定に使用（[2026年1月1日現在の原表](https://www.pref.hokkaido.lg.jp/fs/1/3/1/8/6/7/9/7/_/901brr2601n.xlsx)、外国人を含む総人口）

人口は `src/population.js` に収録し、10万人以上の都市を地図上に常時表示します。札幌周辺の混雑を避けるため江別市のラベルは除外しています。地理的な位置をつかみやすいよう、稚内市・名寄市・留萌市・紋別市・網走市・根室市・富良野市・室蘭市・岩見沢市も表示します。町名は指定された倶知安町・江差町・浦河町だけを表示し、ラベルでは市町村の接尾辞を省略します。人口は上記基準日時点の値で、自動更新はしません。

原データは `data/`、生成済みのSVGパス・市町村情報は `src/municipalities.js` に収録しています。地図の対象は公式一覧の179市町村です。北方領土の図形は集計対象に含めていません。札幌市のコードは市全体の `01100` に揃えています。

地図データの再生成（Python 3、追加パッケージ不要）：

```sh
python3 scripts/prepare-map.py
```
