# 経道値 — 北海道を、あなたの色に。

北海道179市町村の旅行経験を記録する、フロントエンドだけで動くWebアプリです。記録はブラウザーのローカルストレージに保存されます。バックエンド、APIキー、アカウント登録は不要です。

## できること

- 北海道の市町村地図をクリック・タップして記録。地図の拡大・縮小・移動にも対応
- 市町村ごとに「未踏 / 通過 / 接地 / 訪問 / 宿泊 / 居住」の6段階、0〜5ポイントを記録
- 経道値（最大895ポイント）、足あとを残した市町村数、訪問数、宿泊数を集計
- 市町村名・かな・カタカナで検索し、14振興局や経験レベルで絞り込み
- 市町村ごとに200文字までのメモを自動保存
- Xの投稿画面に結果とサイトURLを渡して共有（メモは含めません）
- JSONのバックアップ書き出し・復元、確認操作付きのリセット
- スマートフォン、キーボード操作、動きを抑える設定に対応

「足あと」は通過以上、「訪問」は訪問以上、「宿泊」は宿泊以上の市町村数です。ひとつの市町村につき経験の最高レベルを選びます。札幌市は区に分けず、1市として扱います。初期状態はすべて未踏です。

## ローカルで起動

Node.js 24以上を推奨します（20.19以上の20系、22.13以上の22系にも対応）。アプリの起動・ビルドには外部依存パッケージは必要ありません。

```sh
npm run dev
```

[http://localhost:4173](http://localhost:4173) を開いてください。ポートを変更する場合は `PORT=8080 npm run dev` のように指定します。ES Modulesを使うため、`index.html` を `file://` で直接開かずHTTPサーバーで配信してください。

## ビルド・静的ホスティング

```sh
npm run build
```

生成された **`dist/` の中身**を、GitHub Pages、Cloudflare Pages、Netlifyなどの静的ホスティングへ配置します。サーバー処理やSPA用のリライト設定は不要です。アセットは相対パスなので、`/keidochi/` などのサブディレクトリにも配置できます。

ビルド結果のローカル確認：

```sh
npm run preview
```

ホスティング側の設定は、ビルドコマンド `npm run build`、公開ディレクトリ `dist` です。ブラウザーでの動作に外部CDN、外部フォント、地図APIは使いません。X共有と出典リンクを開くときのみ外部サービスへ移動します。

### GitHub Pagesに公開

[デプロイ用ワークフロー](.github/workflows/deploy-pages.yml)を同梱しています。

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. アプリのソースと `.github/workflows/deploy-pages.yml`、`package.json`、`package-lock.json` を含む変更をコミットして、`main` にpushします。
3. **Actions → Deploy to GitHub Pages** で実行結果を確認します。テスト・ビルドが成功すると、`dist/` が公開されます。

このリポジトリ（`yumu19/keidochi`）の公開先は、標準の設定では `https://yumu19.github.io/keidochi/` です。実際のURLは **Settings → Pages** またはワークフローの `github-pages` 環境に表示されます。リポジトリをforkした場合は、URLのユーザー名とリポジトリ名を読み替えてください。

以降は `main` へのpushで自動更新されます。手動で再公開する場合は **Actions → Deploy to GitHub Pages → Run workflow** で `main` を選択します。`main` 宛てのプルリクエストではテストとビルドだけを実行します。

独自のシークレットや `gh-pages` ブランチは不要です。ワークフローは標準の `GITHUB_TOKEN` とOIDCを使い、公開ジョブにだけPagesへの書き込み権限を付与しています。アセットは相対パスなので、`/keidochi/` 用のベースパス設定も必要ありません。

設定の詳細は [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) を参照してください。

## 保存とバックアップ

- 保存キー：`keidochi.records.v1`
- 保存形式：`{ "version": 1, "records": { "01100": { "level": 4, "note": "旅のメモ", "updatedAt": "ISO 8601形式の日時" } } }`
- 保存先はブラウザーのオリジン（プロトコル・ホスト・ポート）ごとです。端末やブラウザーを変えても自動では同期されません。
- ブラウザーのデータ削除で記録も消えます。プライベートブラウズでは終了時に消える場合があります。「データ管理」からバックアップを残してください。
- 復元は現在の全記録を置き換えます。形式と内容を検証し、画面での確認後に反映します。
- 保存できない場合はエラーを表示します。壊れた保存データを検出した場合は、読み込みや明示的なリセットを行うまで記録を停止して既存データを保護します。
- X共有の投稿内容は経道値・足あと数・ハッシュタグ・サイトURLです。メモや市町村別の詳細は共有しません。ローカルプレビューのURLは投稿内容から除外します。

## テスト

```sh
npm ci
npm test
```

Node.js標準のテストランナーと、開発時だけ使用するjsdomで検証します。地図データ179件の整合性、ポイント集計、検索、保存と復元、破損データの保護、容量不足時の保存失敗、画面操作、メモの自動保存、X共有、複数タブでの更新、確認付きリセットを対象にしています。jsdomは画面を描画しないため、実ブラウザーでのレイアウト確認は別途必要です。

## データの出典

地図・市町村一覧は北海道の公開データを加工しています（CC BY）。

- [北海道の地図GISデータ【北海道】](https://www.harp.lg.jp/opendata/dataset/1379.html) — 市町村ポリゴン、地名表示用座標
- [道内179市町村／50音別](https://www.pref.hokkaido.lg.jp/link/shichoson/aiueo.html) — 名称・読み・振興局

原データは `data/`、生成済みのSVGパス・市町村情報は `src/municipalities.js` に収録しています。地図の対象は公式一覧の179市町村です。北方領土の図形は集計対象に含めていません。札幌市のコードは市全体の `01100` に揃えています。

地図データの再生成（Python 3、追加パッケージ不要）：

```sh
python3 scripts/prepare-map.py
```
